# 作品集 · 面试陪练 Agent 全流程

四份产出物围绕**同一个产品**（面试陪练 Agent）做，串起来是一条完整的产品链路：

```
需求树  →  PRD  →  可点击原型  →  验收测试报告  →  迭代结论
结构      规则       交互            验证              下一版
```

为什么不做五个零散项目：仓库能证明"会动手"，一条走完全流程的链路才能证明"懂产品"——AI 产品岗筛的是后者。

---

## 四份东西分别是什么

| 文件 | 里面有什么 | 对应岗位要求 |
|---|---|---|
| `01-需求树.md` | 三级结构（模块 → 功能 → 细节），每项标 P0/P1/P2，含"不做"清单 | 需求拆解、优先级判断 |
| `02-需求说明书.md` | 背景与目标（带指标）、用户故事、19 条功能需求（**每条都有验收标准**）、泳道图与异常清单、四状态设计 | PRD 写作、边界意识 |
| `03-验收测试报告.md` | 10 条用例的真实执行结果、3 条缺陷（含严重程度与复现路径）、上线结论与下版建议 | 验收测试（UAT）、能不能上线 |
| `04-可点击原型.html` | 三个页面真的能点通：首页（正式档可加简历 + 多份作品集）→ 对练中 → 复盘。定位是**早期的移动端（375×812）概念探索** | 线框图 / 原型 |

附：`证据/` 是测试与复盘的原始记录，报告里每个数字都能在这里对上。

`05-Figma操作手册.md` 是**内部工作文档，不随简历投递**：记的是怎么把这个产品在 Figma 里重搭成设计稿（画板、样式、组件、连线、交付），给自己照着做用的。对外只给 Figma 文件链接，不给这份手册——手册是过程，链接才是产出。

`figma/` 是设计稿的源：

| 文件 | 是什么 |
|---|---|
| `svg/01-首页.svg` `02-对练中.svg` `03-复盘.svg` | **最省事的一条**：直接拖进 Figma 就是三屏，文字是真文本层、图标是真矢量，不用装插件 |
| `目标效果.html` | **目标态对照页**：三屏终稿 + 四组组件的所有变体 + 原型连线 + 10 条验收清单。做的时候开着它，边做边对 |
| `三屏设计稿.html` | 上面三个 SVG 的源：三屏 1440×900 自包含 HTML，尺寸颜色对齐 `web/style.css` |
| `01-屏@2x.png` `02-屏@2x.png` `03-屏@2x.png` | 上面那份 HTML 渲染出来的效果图，1440×900 两倍图，和 SVG 逐像素对齐 |

`dev/html2svg.py` 负责从 HTML 生成这三个 SVG（导出后会把 SVG 渲染回图、和原稿比差），改完设计稿重跑一次就行。

注意：`04` 是 375×812 的**手机**概念稿，`figma/` 是 1440×900 的**桌面**稿。两者不是一套东西——桌面稿对齐已上线产品，手机稿是早期探索。面试时按「先做移动端概念验证，再决定落到桌面 Web」讲。

## 怎么用

**需求树**：Xmind → 文件 → 导入 → Markdown，选 `01-需求树.md`，直接出图，再导出 PNG。
**原型**：双击 `04-可点击原型.html`，用浏览器打开就能点。要给面试官看，可以截图三张，或者直接开这个文件演示。
**PRD 与测试报告**：Markdown 可以直接粘进 Word / 飞书文档，粘之前把标题层级（`#`）转成 Word 的标题样式，目录就能自动生成。
**设计稿**：照 `05-Figma操作手册.md` 搭一遍（约 4 小时），产出一个能分享的 Figma 链接。手册里有 2 小时 / 3 小时的砍法，时间紧就先只做首页那一屏——**但要做成真结构，不要导 SVG 或整张图垫底**，死图层改一个字就崩。

**交给面试官之前，把 `〈填你的名字〉` 换成你的名字，把版本号和日期核对一遍。**

## 对外怎么给链接（简历 / 作品集 / 现场）

Figma 有两种链接，用途完全不同：

| 链接 | 打开后是什么 | 给谁 |
|---|---|---|
| `figma.com/proto/…` | 直接进演示模式，一屏大图，能点，看不到图层 | **简历**、HR、初筛 |
| `figma.com/file/…` | 设计文件，左侧有图层树和页面列表，能翻组件库 | 作品集正文、复面、面试官 |

**别把 `/file/` 放简历。** HR 点开看到的是 Figma 编辑界面——工具栏、图层面板、一堆紫色菱形，第一眼是"一个工具"而不是"一个产品"，三秒内看不到界面就关掉了。`/proto/` 打开就是首页大图，点「开始对练」直接跳 02，这才是简历需要的效果。

三个场景分别这么放：

| 场景 | 放什么 | 放哪儿 |
|---|---|---|
| 简历 | `/proto/` 一条，短链接 | 跟在「面试陪练 Agent」这个项目条目的最后一行，**不要放页眉** |
| 作品集文档 / PDF | 三张 @2x 截图 + `/proto/` + `/file/` | 项目正文末尾，截图在前、链接在后 |
| 邮件 / 私信 / 面试现场 | 两个链接 + 一句"怎么看" | 正文里，别只甩链接 |

简历那条长这样（一行放得下就别换行）：

```
面试陪练 Agent｜AI 语音面试陪练（个人项目）        2026.08–2026.11
· 语音多轮对练 + 逐题复盘；规则树控制澄清/追问/换题上限，10 条验收用例全过
· 交互稿 figma.com/proto/〈ID〉 · 代码 github.com/zyyomg/interview-coach-agent
```

为什么放项目条目里而不是页眉：HR 扫简历是"扫项目"，链接跟在项目后面，上下文自解释；页眉那个孤立链接既容易被忽略，也容易被 ATS 截断。另外**链接写成纯文本**（不要只做超链接文字），招聘系统把 PDF 转文本时超链接会丢，纯文本还能被复制。

作品集文档里要**先图后链接**：很多 HR 拿到的是打印件或转码后的 PDF，链接点不动，图和结论必须自足；链接是给愿意深看的人准备的加餐。

私信/邮件里加一句怎么看，能显著提高对方真的点开的概率：

> 设计文件（可看三屏和组件库）：figma.com/file/〈ID〉
> 可点击原型（点「开始对练」走主流程）：figma.com/proto/〈ID〉

复制 `/file/` 链接前先在画布空白处点一下取消选中，否则链接会带上 `?node-id=…`，对方一打开就跳到某一屏，看不到封面。

## 面试怎么讲（三句话）

> 1. 我做了一个 AI 面试陪练工具，用语音多轮对话模拟面试官，答得含糊就追问，答完给逐题复盘和参考答法。
> 2. 产品上我把判定逻辑做成了一条**有上限的规则树**：澄清、追问、换题、推进各有次数限制，任何一个动作到上限就强制推进——因为最糟的体验不是问得难，是卡在同一题上出不来。
> 3. 交付前我自己写了 10 条验收用例跑了一遍，覆盖空回答、超长回答、连续说不会、重复提交这些边界，结果 10 条全过，但留下了 3 条缺陷，其中"重复提交会白吃一个话题"是接多人之前必须修的。

**如果被追问"这个需求怎么来的"**：先讲用户故事里那个"简历上写了日活 400，怕被追问"的场景——这是真实痛点，不是拍脑袋。然后讲你为此做的取舍：为什么不做题库（题库会过期，模型按岗位名出题够用）、为什么不做账号体系（定位是本地单人练习）。

**如果被追问"你怎么验证的"**：直接翻测试报告。**不要背数字，翻给他看**——能翻出原始记录，比说"我测过了"有力得多。

## 这套东西的边界（说清楚反而加分）

- 评分是模型自评，不是盲评；只有作者一个用户，样本量为 1，**不主张泛化结论**；
- 语音相关的三项（真麦识别、播报打断、外放回声）本轮没测，已写进"下轮必测"；
- 需求树和 PRD 是**事后补写**的，但规则、阈值、异常处理都来自真实代码，不是编的文档——这一点面试时主动说，比被问出来强。
