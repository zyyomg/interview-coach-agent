01 问题

准备面试的人不缺题，
缺的是开口的机会和被纠错的机会

现有做法为什么解决不了
真人模拟面试
¥300–800 / 小时		 约人、约时间都麻烦，一场只能覆盖一家公司；投递量大的人练不起。
对着镜子练没有追问。练的是背稿，不是应答。
刷题库知道"该说什么"，不知道"说得够不够具体"。真实面试里被杀掉的往往是数据说不清，不是不会答。
核心洞察：AI 产品岗的面试官会追着简历上的一个数字问三层，答不上来就判定"这段经历是包装的"。
这种追问压力，只能靠反复被追问来练——而这件事恰好是可以自动化的。

目标

10分钟打完一场
8个话题，到上限自动收尾
¥0.05单场成本上限（实测更低）

给谁做

求职 AI 产品经理 / 产品经理实习的在校生与转岗者。有时间、缺机会、预算低，投递量大——一家公司一场面试。

不做什么（明确划出去）

1不做真人面试的替代品——定位是高频低成本的练习工具
2不做题库——题目由模型按岗位名生成，不人工维护题集，因为题库会过期
3不做账号体系与云端——本地跑，数据留在自己机器上
4不做视频面试、不做简历优化建议——各有各的问题域，混进来会让复盘失焦

两个用户故事

故事一（体验式，练表达）
「我明天要面一家 AI 公司，不知道会被问什么。我想先随便打一场，看看自己一开口是不是又在背概念。」
→ 打开就点开始，不问岗位以外的任何信息；8 个话题打完，复盘告诉我「你有 4 次回答没给数字」。
故事二（正式，练简历）
「我简历上写了日活 400，我怕被追问。我想让面试官就盯着我简历问。」
→ 上传简历 → 开场就问「这个 400 是怎么统计的」；我含糊过去，它追到「哪个后台、打开算还是登录算」。

02 结构

四个模块，19 条功能需求，
每条都带验收标准

优先级只有两档：P0 没有它产品不成立；P1 影响体验但可延后。下面列的是 P0。

1 · 面试对练

  • 开局四项配置：岗位 / 话题数 / 难度 / 面试方式
  • 判定四种动作：澄清 / 追问 / 换题 / 推进
  • 每题动作上限各 2 次，到上限强制推进
  • 语音按句播报，播报中可被打断，打断即停
  • 识别断线退避重连（4/7/12/20/30 秒），不结束本场

2 · 复盘

  • 总分 0–100 + 20 字内总评
  • 3 条优势必须引用候选人原话
  • 3 条改进，每条含问题 + 可执行改法
  • 逐题四件套：点评 / 思路 / 该备的数 / 60–90 字参考答法
  • 模型返回不完整就说"这次没有范本"，不编造

3 · 数据与统计

  • 本次指标：追问 / 澄清 / 换题 / 打断次数
  • 首字延迟、首音延迟
  • 成本逐轮累加接口返回的 token，分时段计价
  • 接口没给用量时退回估算并标注，不冒充实测
  • 往期场次可回看复盘

4 · 明确不做

  • 不做题库：岗位题由模型生成
  • 不做账号体系：本地单机
  • 不做视频面试：语音已经够用
  • 不做简历优化建议
  • 不做作品集排版评审：只拿它出题，不评价好不好看

几条能看出「边界意识」的验收标准

编号需求验收标准（节选）
F05面试方式只给作品集不给简历 → 仍然拦下。正式场要的是「人」，不是产物
F06简历导入扫描件 / 图片型 PDF 读不出字 → 明确提示另存或粘贴，不静默降级；正文不落盘，只记文件名与字数
F11动作上限连续 4 次「不知道」后必须推进到下一话题，不得卡死
F16逐题复盘模型返回不完整时明确说明「这次没有范本」，不假装有

为什么验收标准写到这个程度：「不静默降级」「不假装有」这种要求写在需求里，才不会在实现时被省掉。产品经理能守住的东西，往往就是这几句「不许」。

日期改了什么为什么改

03 核心机制

一条有上限的判定树：
宁可问得浅，不能把人钉死在一道题上

候选人说完一段话，系统按固定顺序判定该做什么。顺序不能乱——它是产品行为本身。

顺序条件动作为什么排在这
1识别为空，或实字数 = 0澄清没听见 ≠ 答得差
2命中放弃词，且占全文 1/4 以上换题"不知道"只有 3 个字，但语义明确
3实字数 < 4澄清语气词当没说清处理
4本题追问已达 2 次推进到上限必须走
5实字数 < 22（困难档 34）追问偏短 = 没展开
6没有数字，也没有结果追问面试最常见的失分点
7其他推进够具体，换话题

为什么要设上限

每题追问、澄清、换题各最多 2 次，到上限强制推进。最糟的体验不是问得难，是卡在同一题上出不来。没有上限的追问，在实现上就等价于死循环。

难度只改三件事

短句阈值（16 / 22 / 34 字）、是否强制要「数字 + 结果」、提问深度提示。判定顺序不变——难度不该改变产品逻辑，只该改变严格程度。

一次真实的翻车：判断词义要看权重，不能只看有没有出现

早期版本里，用户说 200 多字、中间顺嘴一句「不知道从何下手」，系统直接换题了——把一段有内容的回答当成放弃。
修法不是把「不知道」从放弃词里删掉，而是加一个约束：放弃词要占全文 1/4 以上才算放弃。同一个词，在「不知道」和「这个细节不知道从何下手，但整体思路是……」里不是一个意思。

一条交互铁律

任何自动行为都必须可被用户打断。播报可打断、生成可打断、冷场计时会因为打字而重置，打断之后本轮作废、只出字幕不出声。产品是陪练，不是播放器。

四条异常，四条不同的处理——同样是「出错」，处理方式不该一样：

异常处理
无网络（识别）保留语音，退避重连 4/7/12/20/30 秒，不降级——断线是常态，不该判死刑
无麦克风权限降级为打字，播报继续——识别不可用 ≠ 不能听它说话
引擎假活心跳每 12 秒换新识别器，点一下麦克风立即重连

04 界面

三个页面，一条闭环

01 首页岗位、话题数、难度、面试方式四项，选完即时反馈；只有「正式」模式才展开简历区，且没给简历会被前后端各拦一次。
02 对练中一次只问一个问题，单句上限 60 字。HUD 显示话题进度、追问次数与本场花费。
03 复盘总分 + 3 条优势 + 3 条改进 + 逐题四件套，可下载 .md 并归档。

界面尺寸与配色取自代码 web/style.css（304px 侧栏、14px 基准字号、13px 气泡圆角），设计稿与上线产品是同一套数值体系。

界面上的三个「少」

一次只问一个

单句上限 60 字，超长强制拆句。真人面试官不会一口气抛三个问题；一次问三个，候选人只会挑最好答的那个答。

HUD 只放三个数

话题进度、追问次数、本场花费。练的时候盯着数据看，就练不好表达——数据是复盘时用的，不是练的时候用的。

优势必须引用原话

不引用原话的夸奖等于空话：用户没法验证，也就没法复制。同理，3 条改进每条都要给可执行的改法。

05 设计系统

4 组组件、12 个颜色样式、8 个文字样式

切组件的依据不是「长得像就合成一个」，而是「会不会一起变」。

组件变体属性切分依据
Button4Type × State primary / ghost 是两种按钮；default / hover / disabled 是同一种按钮的三个状态
Seg2State单选控件的两个状态：off / on
Message2Whoagent / me 两侧结构不同（我方无标签行）
Composer1—输入条整体，内部元素不单独成组件

Button 为什么不是四个平铺变体

平铺更快，但会丢信息——「状态」这个概念消失了。拆成两个维度后，规则变成可验证的：同一 Type 下的三个 State，尺寸和内边距必须完全一致，只允许颜色不同。不一致的话，切换状态时按钮会跳。

Message 只做 2 个变体，是取舍

完整形态 6 种（提问/追问/澄清/换题/收尾/我方）。这 6 种差异只有小胶囊颜色和文案，复用价值低于维护成本，静态形态在 02 屏里都有画。这是主动收敛，不是漏做——写进交付说明的「待完善」里。

设计变量与代码同源

设计稿样式名CSS 变量值用在哪
accent--accent#2B55D6主按钮、强调文字、选中态
accent-soft--accent-soft#EEF2FF选中底、标签胶囊底
ink / ink2 / ink3--ink 等#12141A …正文 / 次要 / 提示三级文字
line / line-2--line 等#E6E8EC卡片描边、分隔线

代码的 :root 里共 18 个颜色变量；代码里实际出现 18 种字号（9–24px），设计稿收敛成 8 个文字样式。设计稿相对代码唯一「变少」的地方就是字号——代码是长出来的，稿子得能讲清层级。

验收：90 秒能不能看完

1打开设计文件 → 停在封面页，上面写了产品是什么、文件里有什么、怎么看
2切到「页面」→ 三屏并排，1440 × 900
3右上角 ▶ →「开始对练」→「结束」→「再练一场」，回到首页
4切到「组件」→ 四组组件，选中后右侧面板能看到 Type / State / Who 这些属性
这份稿子的真相：它是产品做完之后反推的，不是先设计后开发。它能证明「把已上线界面抽象成设计系统」的能力，不能证明「从零做设计推演」——这一点写进了交付说明的「已知不足」，不藏着。

06 验证

10 条用例全过，
但结论不是「没问题」

执行方式是脚本调用 HTTP 接口、逐事件解析返回，不是点页面点出来的。每条用例的请求与真实返回都存在 证据/验收-20261108.json 里，可逐条复核。

编号场景实际结果结论
TC02回答偏短（17 字）动作 = 追问；"那十几个人你是怎么选的，访谈完得出了什么结论？"通过
TC03只有语气词「嗯」动作 = 澄清；"声音有点断，刚才那句能再说一次吗？"通过
TC05连续 4 次「不知道」换题 → 换题 → 推进 → 换题，进入第 2 题，没卡死通过
TC07正式模式缺简历HTTP 400，提示"正式面试要读简历……只想随手练就切回体验式"通过
TC09走完 4 话题 + 复盘开场引用简历里的"日活 400"；复盘 58 分，4 条逐题全部带范本通过

另有 TC01 / 04 / 06 / 08 / 10 五条，覆盖体验式开局、555 字超长输入、重复提交、docx 解析、打断计数，全部通过。

三条缺陷（全过只说明设计好的路径通了）

编号问题严重度状态
BUG-01题号显示慢一拍：强制推进时 HUD 仍是旧题号，下一轮才更新轻微待修（1 行）
BUG-02重复提交会白吃一个话题：服务端无幂等键，第二次被当成新回答，直接推进并多花一次调用一般遗留，接入多人前必修
BUG-03识别断连期间说的话无留存，重连后要重说（浏览器不提供音频流，属能力边界）一般不改，靠提示语缓解

能不能上线

可以，作为本地单人练习工具。主流程（开局 → 多轮问答 → 自动收尾 → 复盘带范本）闭环完整，缺简历、重复提交、连续放弃三种异常都不会把用户卡死。
不建议多人共用：没有账号体系和会话隔离，接口无幂等键，多人用会互相污染数据。

一句实话

这 10 条用例是我自己设计的，覆盖的是我知道会出问题的地方（调试时踩过的坑）。它能证明"这些路径是通的"，不能证明"产品好用"。好不好用要看 10 场真人真麦的对练，跑完才有资格说。

用例是怎么设计的：从六个维度各取至少一条——开局配置、判定逻辑、简历解析、复盘产出、异常输入、统计口径；优先测调试时踩过的坑，不测「显然能过」的路径。TC01 的期望值最初写成"首句以问号结尾"被判失败，后来发现是用例写错了、不是产品错了——这一条故意留在报告里，因为验收标准本身也要能被验收。

一个被推翻的估算

PRD 里写的目标是「单场 ≤ ¥0.05」，那是按官方价目算的。实测 8 个话题的一场是 ¥0.0136——低了一个量级，原因是上下文缓存命中了 3712 个 token。
估算和实测差 3 倍的时候，该改的是文档，不是把实测数据往估算上凑。

为什么能这么便宜：成本结构（那一场实测）

项用量说明
输入 token16,374（命中缓存 3,712）简历 + 话题 + 最近 30 轮上下文，轮与轮之间大部分不变
输出 token213面试官一次只说一句话（单句上限 60 字）——成本低不是省出来的，是产品形态决定的
合计¥0.01368 个话题、9 轮回答。输出只有 213 token 是关键——做成「一次给三段建议」的形态，输出会翻十倍，成本优势就不成立

下一步（按优先级）

1跑完 10 场真人真麦对练——把完成率、追问有效性从「目标值」变成「实测值」，这是目前唯一缺的证据
2修 BUG-01；加请求 ID 修 BUG-02（重复提交会白吃话题，多人使用前必须解决）
3复盘把 3 条改进收敛成 1 条（现在给 3 条，用户反而不知道先改哪个）；补外放场景测试——不戴耳机时的回声自激，是目前唯一会毁掉整场体验的问题
